## Запуск

Windows 10/11, .NET Desktop Runtime 8, SDK с поддержкой net8.0.
Проверено SDK 10.0.103; в Visual Studio 2022 использовать совместимый SDK .NET 8
и workload классических .NET-приложений. IDE в этой сессии не запускалась.

```powershell
dotnet restore HomeMenu.sln --locked-mode
dotnet build HomeMenu.sln -c Release --no-restore
dotnet test tests/HomeMenu.Tests/HomeMenu.Tests.csproj -c Release --no-build
dotnet run --project src/HomeMenu.Wpf/HomeMenu.Wpf.csproj -c Release --no-build
```

Exe: src/HomeMenu.Wpf/bin/Release/net8.0-windows/HomeMenu.Wpf.exe.
БД: `%LOCALAPPDATA%\HomeMenuCourse\homemenu.db`. Для демонстрации до запуска:

```powershell
$env:HOMEMENU_DATABASE_PATH = Join-Path $env:TEMP 'HomeMenu-defense-demo.db'
```

После демонстрации закрыть приложение и убрать только переменную окружения:
`Remove-Item Env:HOMEMENU_DATABASE_PATH`. Данные в файле останутся; повторное открытие
с тем же путем должно показать сохраненный результат. Рабочую БД удалять не требуется.
Первый запуск создает миграцию и учебный каталог, затем пользователь регистрируется
со своим паролем и заполняет профиль. Seed не создает пользователей или пароли.

## Демонстрация за 5–10 минут

1. Открыть отдельный новый demo-путь, зарегистрироваться. Показать отказ на повтор
   логина с другим регистром и на неверный пароль; войти верным паролем.
2. Профиль: мужской, возраст 20, 175 см, 70 кг, умеренная активность ×1,55,
   бюджет 150 BYN. Нормы: 2633,0625 ккал; Б197,4796875 / Ж87,76875 / У263,30625 г.
3. Открыть общий каталог, поиск «молоко», категорию «молочные»; показать
   «Овсянку с бананом»: 100 г хлопьев + 200 г молока + 120 г банана.
   Одна порция: 606,8 ккал, Б20,32 / Ж13,76 / У105 г, 1,12 BYN.
4. Добавить новый учебный продукт «Демонстрационный» с ценой `0,1234`, исключить
   его в профиле, сохранить. Он не входит в seed-рецепты и не мешает маршруту.
5. Пока не добавлять запасы. Выбрать понедельник текущей недели, свою цель
   **2200 ккал**, **150 BYN**, подобрать меню. Получается 21 запись с дневными
   калориями в 1980–2420. Для неизмененного seed без запасов проверен план
   **15220,1 ккал, 52,369 BYN** (52,37 на экране). Это результат генератора.
6. Выбрать неприготовленное блюдо, «Заменить», выбрать допустимый рецепт того же
   приема пищи. При нарушении дневной границы подтвердить только после просмотра
   новых расчетов; предупреждение останется видимым. Повторная замена на исходный
   рецепт возвращает соответствие ограничениям. При изменении данных во время
   диалога устаревшее подтверждение отклоняется.
7. Показать покупки: потребность, покрытие, дефицит, текущие цены и итог, затем
   статистику: отдельные полная стоимость меню, закупка и остаток бюджета.
8. Для завтрака понедельника «Овсянка с бананом» добавить партии без срока:
   хлопья 300 г, молоко 1000 г, банан 500 г. Выбрать этот прием и подтвердить
   приготовление (дата понедельника не позже сегодня). Остатки станут
   **200 г / 800 г / 380 г**, появится отметка времени; повторная команда недоступна.
9. Выйти, закрыть приложение, открыть с тем же demo-путем и войти снова:
   должны остаться меню, партии и одно приготовление. Это ручной пункт приемки,
   автоматическая версия повторного чтения БД уже пройдена.

Временная цена/состав, добавленные на шаге 4, не меняют seed-расчет, потому что
продукт исключен и не входит в рецепты. Добавление запасов на шаге 8 происходит
после генерации: повторный подбор с другими остатками может дать иной допустимый план.

## Отрицательные сценарии

- Для новой недели поставить бюджет 0: NoSolution, прежняя неделя не исчезает.
- Исключить все продукты начального каталога: NoCandidates; затем снять исключения.
- Перед приготовлением оставить только 80 г хлопьев: полный отказ с дефицитом 20 г,
  молоко/банан и статус не меняются. Пополнить партию и повторить.
- Отказаться в диалоге приготовления: изменений нет; после успеха повтор запрещен.
- Попробовать приготовить будущий день: кнопка недоступна; сервис тоже запрещает.
- Выбрать вторник как начало недели: сообщение о необходимости понедельника.
- В тестах отдельно проверены отмена на узле 10, MaxVisitedNodes=0/1/20,
  сохранение старой недели при сбое записи и изменение каталога во время поиска.
  В обычном seed поиск быстрый, поэтому успеть нажать отмену вручную может быть трудно.
- После первого приготовления перегенерация недели запрещена, замена других
  неприготовленных приемов остается возможной.
