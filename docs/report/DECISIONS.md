# Принятые решения

Дата реализации и проверок: 28.10.2026 (Africa/Nairobi).

| Решение | Причина и реализация | Влияние на записку |
| --- | --- | --- |
| Новый HomeMenu.sln | Текущая папка и origin были пустыми; полезного кода/изменений пользователя не было | Описывать фактически созданную структуру |
| C# 12, net8.0, WPF, MVVM, EF8, SQLite | Сохранен контракт задания | Автор Стреха; предметная область домашнего меню |
| EF Core / Design / dotnet-ef 8.0.24 | Доступный исправляющий выпуск ветки 8.0, прошедший сборку и SQLite-тесты | Заменить исходное 8.0.10 на точные версии; не называть стек «самым актуальным» |
| Нет global.json | Установлены SDK 9.0.311 и 10.0.103; проверен 10.0.103, не выдумывается SDK 8 | Для VS2022 использовать его совместимый SDK .NET 8; запуск VS не проверен |
| INTEGER с явным масштабом | AppDbContext.ToScaled и value converters, CHECK по физическим колонкам | Не приписывать HasPrecision гарантии SQLite decimal |
| Девять сущностей | Исходные шесть плюс MenuPlan, MenuIngredientSnapshot, UserExcludedProduct | Добавить технические сущности и исторические снимки |
| Пять контрактов, один фасад HomeMenuService | Auth, Profile (включая предпочтения), Catalog (продукты и рецепты), Pantry, Menu (включая покупки и статистику); короткие контексты | Таблица предложенных сервисов гайда объединена; использовать реальные имена из CODE_MAP |
| Все операции сериализованы Gate | Встроенный SQLite; чтения короткие, поиск выполняется вне блокировки | Нет generic repository, фоновой работы с отслеживаемым DbContext или сервера БД |
| Revision и SessionTicket | Результат долгого поиска отклоняется при записи других данных, смене сеанса или даты | Уточнить повторную проверку актуальности до транзакции |
| ProfileInput и FormField | Редакторы создают отдельные входные модели; EF-объекты UI не записывает самостоятельно | Не описывать бизнес-расчеты в code-behind |
| Общий EditorWindow | Одно представление полей плюс таблица ингредиентов; проверки возвращают название поля в сообщении внизу редактора | Нет отдельных ProductEditorWindow/RecipeEditorWindow, нет обещания подсветки каждого поля |
| 17 продуктов / 9 рецептов | Идемпотентное первоначальное заполнение пустого каталога одной транзакцией; учетных записей в рабочем seed нет | Цены и питание учебные, не магазинный прайс |
| Только граммы, BYN и одна порция | Уточнение гайда, а не дословная цитата исходника | Убрать обещание произвольных единиц и семейного масштаба |
| Бюджет строгий, калории 90–110%, БЖУ для сравнения | MenuGenerator и PlanAnalysis | Различать полную стоимость ингредиентов и закупку; не обещать строгий баланс каждого макронутриента |
| WPF smoke — отдельный проект | tests/HomeMenu.UiSmoke открывает настоящие Views на синтетической БД; в продукте нет обхода входа | Отдельно описать автоматические UI-проверки и ручные действия |
| Снимки через RenderTargetBitmap | Содержимое фактически открытых окон после WPF layout; native pipe Computer Use недоступен | Не называть снимки захватом рабочего стола или доказательством ручного кликового маршрута |
| Без Word; push после прямого поручения | START_CODEX запрещал самостоятельную публикацию; 28.10.2026 владелец явно поручил разбить изменения на коммиты и отправить main | Код и тесты: eaca1373111486bccd7d6e03be66e960cd4fb828; документация — следующим коммитом, Word не создается |

Уточнения 01_CONTEXT.md приняты полностью: стоимость всех ингредиентов, годность на дату использования,
FEFO, объединение текущих и сохраненных исключений, сохранение снимков и запрет повторного приготовления.
Содержательного сокращения функций R01–R15 нет. Ручная проверка и Visual Studio остаются отдельными ограничениями проверки.
