# Шаблон итоговой передачи

Codex заполняет этот шаблон фактами в `docs/report/HANDOFF.md` после реализации. Здесь нет предварительно выполненных проверок.

## Состояние исходников

- Название solution и пути основных проектов.
- Ветка, фактический HEAD; отдельно сообщить о незакоммиченных изменениях.
- Если репозиторий уже опубликован по поручению владельца — публичный URL и точный commit проверенного кода.
- Реализованные R01–R16; неполные требования перечислить отдельно с причиной.

## Запуск

Указать проверенные предварительные условия, точные команды restore/build/test/run, путь БД и способ выбора отдельной демонстрационной БД. Описать первый запуск: зарегистрировать пользователя, заполнить профиль, выбрать план. Не передавать пароль реальной учетной записи.

## Демонстрация за 5–10 минут

Дать воспроизводимые шаги для чистой БД с реальными значениями профиля, цели и бюджета, при которых seed позволяет создать меню. Показать продукты и состав рецепта, партии с годностью, исключение, генерацию, ручную замену, покупки и одно подтверждение приготовления. Привести ожидаемый числовой результат хотя бы для одного блюда и изменения остатков.

Отдельно дать отрицательные сценарии: слишком маленький бюджет, исключение всех блюд одной категории, нехватка продукта, отмена и повторное приготовление. Указать, как после демонстрации открыть тот же файл и убедиться, что результат сохранился. Очистку рабочей БД пользователю не предлагать как единственный способ повторить проверку: использовать отдельный путь.

## Проверки

Таблица: команда/сценарий → платформа и версия → фактический результат → ссылка на лог/тест. Для недоступного Windows UI использовать NotRun/Blocked и дать точные ручные шаги. Указать количество реально существующих/выполненных тестов только после запуска. Приложить ссылку на TEST_RESULTS.md.

## Для будущего Word

- Ссылки на CODE_MAP, DATABASE, ALGORITHMS, VERSIONS, DECISIONS, LIMITATIONS.
- Какие разделы 1–2 исходной записки требуют исправления по фактическому коду.
- Какие схемы готовы и где их исходники.
- Какие скриншоты действительно получены с Windows, а какие еще нужны.
- Что реализовано иначе, чем в гайде, и почему.

## Остаток работы

Назвать конкретные невыполненные функции и проверки. Если все обязательные функции завершены, сказать об этом с опорой на результаты. Не завершать формулировкой «осталось только UI», если запрошено рабочее приложение. Не скрывать ограничения среды за общим «готово».

После реализации владелец передает в исходный чат публичный URL репозитория и согласуемый commit SHA. По нему будет выполнена независимая сверка и затем создан Word-раздел. До этой проверки не утверждать, что согласование кода и отчета уже состоялось.
