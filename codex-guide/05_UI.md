# Экраны и поведение интерфейса

Русскоязычный WPF-интерфейс должен быть законченным и пригодным для демонстрации. Использовать единые отступы, подписи единиц, читаемые таблицы, явные кнопки действий и понятные пустые состояния. Не тратить основной объем на анимацию и декоративные панели. Указывать валюту BYN, вес в граммах, нутриенты и цену за 100 г.

## Навигация

Окно входа/регистрации → основное окно с разделами «Профиль», «Продукты», «Рецепты», «Холодильник», «Меню на неделю», «Покупки», «Статистика». Кнопка «Выйти» доступна из основного окна. Исключения редактируются в профиле или отдельной вкладке профиля. Это предлагаемая организация: эквивалентная навигация допустима с фиксацией фактических Views/ViewModels.

| Экран | Данные | Действия и обязательные состояния |
| --- | --- | --- |
| Вход | Логин, PasswordBox | Войти, перейти к регистрации; неверные данные и занятость |
| Регистрация | Имя, логин, пароль и повтор | Создать запись, вернуться ко входу; ошибки возле полей |
| Профиль | Параметры тела и активности, бюджет, нормы | Сохранить, выбрать исключения; указать неполный профиль |
| Продукты | Общий каталог с показателями на 100 г | Поиск, категория, добавить, изменить, удалить; причина запрета удаления |
| Рецепты | Список и карточка одной порции | Фильтры, редактор ингредиентов, инструкция, КБЖУ и стоимость; нет совпадений |
| Холодильник | Партии пользователя, граммы, годность | Добавить, исправить, удалить; просроченные явно отмечены |
| Меню | Семидневная сетка × три приема | Выбор понедельника, цель/бюджет, генерация/отмена, замена, приготовление |
| Покупки | Потребность, пригодный запас, дефицит, цена и сумма | Пересчитать для выбранного плана; сообщение «Все продукты уже есть» |
| Статистика | КБЖУ дня/недели, цели, стоимость, приготовлено | Выбор недели; пустой план, предупреждения о ручных нарушениях |

## Меню

В ячейке показывать название, КБЖУ и стоимость порции, отметку приготовления. При выборе открывать инструкцию и снимок ингредиентов. Цель, недельный лимит и полная стоимость недели должны быть видны вместе. После ручной замены все связанные показатели и покупки пересчитываются. При нарушении ограничений показывать конкретную причину: например, «Среда: 1680 ккал при допустимых 1800–2200».

Не отображать кнопку приготовления для будущей даты как доступную. Повторное приготовление заблокировано в UI и сервисе. У еще не приготовленного блюда с новым исключением показывать предупреждение. Изменение запасов не должно убирать рецепт из плана самопроизвольно.

Во время генерации показывать «Подбор меню…» и активную отмену. Не выводить выдуманный процент прогресса; число посещенных узлов допустимо. Отключать конфликтующие записи на уровне интерфейса, но сохранять повторные сервисные проверки. Не допускать зависания окна при поиске на 100 000 узлов.

## Подтверждения и ошибки

Подтверждение необходимо перед удалением, заменой существующей недели, сохранением вручную нарушенных лимитов и списанием при приготовлении. Сообщение о приготовлении перечисляет расход; отказ не вызывает сервис записи. Подтверждения не нужны на обычное чтение, поиск и пересчет покупок.

Показывать различающиеся сообщения для отсутствия кандидатов, полного отсутствия решения и исчерпания лимита поиска. Пример последнего: «За установленное число попыток подходящее меню не найдено. Ослабьте ограничения или увеличьте лимит поиска». Это не доказательство несовместимости всех ограничений.

Ошибки валидации, конфликт версии, нехватка запасов, занятость и ошибка файла БД обрабатываются понятными сообщениями. После ошибки сохранять введенные пользователем значения. Ожидаемые бизнес-ошибки не показывать как stack trace. Непредвиденную ошибку фиксировать технически без паролей; не объявлять операцию успешной до commit.

## MVVM

ObservableObject/INotifyPropertyChanged, команды с CanExecute, ObservableCollection и привязки XAML. В code-behind разрешены передача PasswordBox, события окна и другие действия представления; бизнес-правила и запросы к БД там не размещать. AsyncCommand блокирует повторный запуск и корректно возвращает состояние доступности при исключении. Диалоги реализовать через небольшой сервис для проверяемости ViewModels.

Для ru-RU поддержать десятичную запятую; допустимо также принимать точку однозначным парсером без разделителей тысяч. Нельзя трактовать «1,5» как 15. Запретить ввод произвольной даты начала недели без сообщения; DatePicker выбирает/нормализует понедельник явно. Перед закрытием редактора с несохраненными изменениями запросить подтверждение потери ввода.

Итоговые скриншоты получать только с настоящего запущенного приложения на Windows. Нельзя создавать картинку интерфейса и использовать ее как свидетельство работающего WPF.
