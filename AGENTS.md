# Инструкции по курсовому проекту HomeMenu

## Цель

Реализовать настольную программу автоматизации составления домашнего меню по `codex-guide/`. Автор проекта — Стреха Анна Владимировна. Гульченко Владислав — автор приложенного примера другого проекта. Смешивать авторство, предметные области и имена модулей запрещено.

## Обязательные действия

- Прочитать все файлы `codex-guide/` до реализации. Использовать исходники из `sources/` для проверки контекста.
- Осмотреть существующий код и локальные инструкции. Сохранить изменения пользователя.
- Реализовать рабочие сценарии, а не заглушки или неподключенные экраны.
- Сохранить C# 12 / .NET 8 / WPF / EF Core 8 / SQLite. Применить ООП и MVVM. Не добавлять веб-сервер, Docker, внешние API или облачную БД.
- В сервисах повторно проверять права на пользовательские данные, ввод и допустимость операции. Скрытая кнопка не заменяет проверку.
- Не записывать открытые пароли. Использовать библиотечный `PasswordHasher<User>` с солью и проверкой хеша.
- Расчеты денег и питания проводить в `decimal`; учитывать ограничения EF Core 8 с SQLite. Правила хранения описаны в гайде.
- Все изменения остатков и состояния приготовления сохранять атомарно. Не допускать повторного списания.
- Генератор должен завершаться, обрабатывать отсутствие решения и не уничтожать старое меню при неудаче.
- Указать реальные результаты сборки и тестов. Не выдавать сборку WPF в Linux за проверку интерфейса Windows.
- По каждому изменению поведения обновлять `docs/report/`. Перед передачей устранить расхождения между кодом, тестами, README и документацией.

## Приоритет источников

Явные новые указания владельца → бланк задания → функциональные требования первой процентовки Стрехи с явными уточнениями гайда → этот гайд в вопросах реализации → пример Гульченко только по форме и глубине описания. При противоречии в нумерации этапов ориентироваться на название раздела «Программная реализация». Изменения решений записывать в `DECISIONS.md`; содержательное сокращение обязательных функций не считать рутинным решением.

## Готовность

Готовность означает: приложение собирается, существенные бизнес-правила проверены, БД создается миграциями, UI связан с сервисами, данные сохраняются после перезапуска, материалы передачи заполнены фактами. Если проверить часть поведения невозможно в текущей среде, явно перечислить непроверенное и точные оставшиеся действия. Отчет Word на этом этапе не создавать.
